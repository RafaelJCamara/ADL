<objective>
Prove the phase's architecture end to end on one thin path: a feature gets a git worktree, a real process runs inside it through the one exec boundary with zero inherited environment, its output streams back as `LogChunk`s, and teardown leaves neither a worktree nor a branch behind.

**MVP user story** (from ROADMAP.md § Phase 2 Goal): **As a** maintainer running ADL, **I want to** have every process ADL launches go through one swappable workspace, **so that** the worker's blast radius is bounded before any adapter exists to break the rule.

Purpose: Task 2 is the tracer. It is production-quality, not a prototype — every line it writes stays. Its job is to catch an architectural dead-end after one commit rather than after ten. Every later plan in this phase expands out from that slice; none of them re-architects it.

**Task shape, and why it is what it is.** Task 1 is declarations and scaffolding — the published type surface in `@adl/core/stage`, the `@adl/workspace` manifest and build configs, one error class, and a barrel. It contains no behaviour, so it is not a horizontal layer of the tracer: there is nothing in it to run end to end, only something to compile. Task 2 is the single vertical slice — the process-launch path and the git-worktree lifecycle wired together and proven by one integration test against a real git repository — and it remains the first behaviour this phase commits and the first thing verified end to end. The split exists because the previous revision put fifteen files in one task, and the predicted degradation was that `run.ts`'s execa option set would be written thinly with attention already spent on `tsconfig.json`. Scaffolding is cheap to get right and expensive to be distracted by.

Output: `@adl/workspace` exists and is enrolled in the test runner; `Workspace` is a real interface rather than a forward declaration; one committed integration test walks the whole path against a real git repository.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker process → child process | `Workspace.exec()` is where ADL's own process environment stops and the agent's begins. Everything the child can read, it can exfiltrate in its output. |

| `@adl/core/stage` → third-party harness | The published `Workspace` interface is consumed by code ADL does not own. Its shape is a contract, and a member that leaks a host path or a credential leaks it to every harness. |

## Planner assumptions (probe-surfaced, unresolved)

These four probe rows came back `unclassified`. Per the fallback protocol an `unclassified` row is never auto-resolved and never auto-dismissed — it is carried forward as an explicit assumption for a human to close.

The pattern list is therefore a maintained artifact; a credential shape absent from it is not detected.
