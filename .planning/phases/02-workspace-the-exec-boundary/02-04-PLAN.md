<objective>
Make reclamation true continuously rather than only right after a sweep: teardown at terminal state removes both the worktree and the branch, in the only order git permits, idempotently — and a backstop sweep collects whatever a crash left behind.

**MVP user story** (from ROADMAP.md § Phase 2 success criterion 1): **As a** maintainer running many features through ADL, **I want to** find no leftover worktrees and no leftover `adl/*` branches in my repository, **so that** a long-running daemon does not slowly turn my repo into a graveyard.

Purpose: `02-RESEARCH.md § Pitfall 3` reproduced the failure this plan exists to prevent — `git worktree remove` does not delete the branch, and `git worktree prune` does not either. A teardown built on either alone satisfies "no worktree" and quietly fails "no branch", and after thirty features the repository has thirty stale branches nobody notices. `§ Pitfall 4` and `§ Pitfall 9` fix the order and force the `--force`.

Output: hardened `createWorktree`/`destroyWorktree`, a porcelain inventory parser, and `sweepOrphans` — with the database reached through an injected lookup so the swappable backend stays database-free.

**Boundary note — a recorded deviation from D-20's literal split, not an implementation of it.** D-20 reads: *"`packages/workspace` exposes `listManagedWorktrees()` and `destroy()` and takes no `@adl/db` dependency; **the manager owns the sweep** that joins that inventory against `featuresRepository`."* This plan puts the join itself — `sweepOrphans` — inside `packages/workspace`, expressed over an injected `FeatureStateLookup` rather than over `featuresRepository` directly. Say what that does and does not change:

- **D-20's substance is preserved and mechanically asserted.** `packages/workspace` still takes no runtime database dependency; Task 3's manifest checks prove it from both directions. The dependency *direction* — the property D-20 exists to protect, and the thing that keeps the backend swappable — is untouched.
- **What changed is the file the join function lives in, and why.** Success criterion 1 ("many features created, then a GC pass leaves no worktree and no `adl/*` branch") is not testable in Phase 2 at all if the pass exists only inside a manager process that does not yet exist. Relocating the pass is what makes the criterion checkable at the end of this phase rather than deferred to Phase 3 along with everything else.
- **The manager still owns the binding**: wiring the lookup to `featuresRepository.findById`, running the periodic backstop schedule, and exposing the manual trigger as a CLI verb (D-15). All three are Phase 3 work because neither a manager process nor a CLI package exists yet. This is recorded in `02-CONTEXT.md` under D-20 and in its § Deferred Ideas, so **a later verifier reading D-20 literally does not flag the manager as missing sweep work it never had.**
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent-written worktree contents → teardown | The agent controls the worktree's contents at teardown time and can make removal fail (open handles, unreadable files, leaked processes). A teardown that gives up leaves both a worktree and a branch. |
| feature state store → collection decision | The state lookup is what authorises destroying a directory. A wrong or stale answer destroys work. |

| T-2-11 | Denial of Service | teardown leaves the branch behind, so `adl/*` branches accumulate without bound across the daemon's lifetime | high | mitigate | Task 1's two-step teardown with both halves asserted in the test; Task 3's sweep as the backstop for whatever a crash skipped. |
| T-2-12 | Tampering | the sweep collects a live feature's worktree and destroys uncommitted agent work | high | mitigate | Feature state is the only signal (D-16); `TERMINAL_STATES` is imported rather than transcribed so `escalated` is spared automatically; the test asserts the escalated and running worktrees survive.
