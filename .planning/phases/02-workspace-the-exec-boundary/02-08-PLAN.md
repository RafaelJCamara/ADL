<objective>
Close the last and least obvious path from an agent's worktree back into ADL: the git configuration a linked worktree shares with the main repository. Every ADL-side git invocation neutralises the executable configuration keys, runs from an ADL-owned home, and launches through the same one exec boundary the worker uses.

**MVP user story** (from ROADMAP.md § Phase 2 success criterion 4): **As a** maintainer whose repository ADL is running agents inside, **I want to** know that a hook path an agent wrote cannot execute during ADL's own git operations, **so that** "agent-written configuration never affects ADL's own git" is a property of the code rather than a sentence in a document.

Purpose: `02-RESEARCH.md § Pitfall 5` is the most important finding in this phase and it was reproduced locally. A linked worktree does not have its own local configuration — it shares the main repository's. Writing `core.hooksPath` from inside a worktree writes the **main** repository's configuration, and reading it back from the main repository returns the planted value. D-08 protects the global and system scopes and was confirmed working, but neither scope touches local, and git upstream has stated it has no plans to make dangerous local-configuration directives safe. There is no fix coming, so ADL neutralises them itself.

D-19 names the third control this needs; D-17 says the manager's git client gets there through its own `Workspace` instance rather than through a second lint exemption, which keeps success criterion 2 literally true and applies the neutralisation by construction.

Output: a host-rooted backend registered beside `'worktree'` and `'stub'`, one manager git client, and the test that makes the property real.
</objective>

    Its `create` returns a `Workspace` whose `root` is the main repository path and whose `scratchHome` is **not** a per-run temp directory but an ADL-owned configuration directory the daemon supplies — a stable path outside every feature's scratch root (D-08). The backend itself holds no credential and reads none from the daemon's environment — the caller supplies them, which keeps the credential's lifetime as short as the call.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| feature worktree → main repository local configuration | A linked worktree shares the main repository's local configuration file. An agent writing configuration from inside its worktree is writing a file ADL's own git reads. Reproduced. |
| agent scratch HOME → ADL's git operations | If ADL's own git ran with a home inside or adjacent to the agent's scratch directory, a leftover global configuration would apply to ADL's operations. |
| manager credentials → git subprocess | ADL's own pushes and remote calls need a forge token. That token must never be reachable from a worker-launched child. |
