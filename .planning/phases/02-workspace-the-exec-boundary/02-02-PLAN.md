<objective>
Land the no-direct-spawn boundary as a build property: a lint rule that fails CI when any module outside `packages/workspace` launches a process, in any of the three import forms, and that provably does not erase the rules Phase 1 already relies on.

**MVP user story** (from ROADMAP.md § Phase 2 Goal): **As a** contributor to ADL, **I want to** have the build reject a direct process spawn the moment I write one, **so that** the container backend in v2 is a registry entry rather than a repository-wide call-site sweep.

Purpose: success criterion 2 is a *build* property, not a review property. `02-RESEARCH.md § Pitfall 1` and `§ Pitfall 2` each describe a way this rule ships looking correct while being hollow — overlapping flat-config entries silently deleting `@adl/core`'s purity bans, and `no-restricted-imports` being blind to `require()` and dynamic `import()`. Both were reproduced locally against this repository's own ESLint 10.8.1.

Output: a rule composed as one complete object per `files` glob, three deliberate-violation fixtures, and a regression guard that fails if the Phase 1 bans stop resolving.

This plan is deliberately independent of the `packages/workspace` package. It runs in Wave 1 alongside the legitimacy gate, before the module it protects exists — which is D-27's whole argument, applied to the exec boundary: the rule lands before any adapter exists to break it.
</objective>
