<objective>
Make success criterion 4 true: *"Repository-level agent-CLI config auto-discovery is disabled and
system prompts are set explicitly, so the same feature on the same commit receives the same prompt
twice running."*

Purpose: two separate risks share one criterion. The first is contamination — a watched repository's
own agent configuration joining the prompt without ADL asking, which `04-RESEARCH.md` records the
vendor's own documentation warning about: without the reproducibility flag, a headless session loads
a project's settings and hooks in a folder nobody ever trusted. The second is drift — a renderer
that interpolates a timestamp, a host path, or an unordered map, making two runs on one commit
differ for reasons nobody chose.
Output: an explicitly-supplied context surface, a renderer with the three non-determinism sources
absent by construction, and a persisted prompt artifact per attempt that makes the claim checkable
after the fact.
</objective>

    Prove the criterion the way it is worded — *the same feature on the same commit receives the same
    prompt twice running* — by comparing two real attempts' persisted artifacts, not by calling the
    renderer twice in one process. A same-process comparison cannot catch the failures that matter:
    a value captured at module load, a path that differs by working directory, an environment
    variable that happens to be identical within one process.

    Start a daemon against a temp repository with one real feature folder and run the same feature
    twice, without changing the commit between them. Read the two attempts' prompt artifacts off
    disk and assert byte equality. Then run the same comparison across two separate daemon
    processes started from different working directories, so a working-directory-derived path or a
    process-lifetime value shows up as a difference rather than hiding.

    Add the adversarial cases that make the assertion mean something rather than merely pass. Render
    with a distinctive environment variable set for the second run and assert the artifacts are still
    identical — if an environment value ever reaches the prompt, this is what catches it. Advance
    the wall clock between the two runs by whatever the test harness allows and assert the artifacts
    are still identical. And add the negative control: change the spec, run again, and assert the
    artifact **differs** — without it, a renderer that returned a constant would pass every
    assertion above.

    Assert the outcome against the file's bytes rather than a hash computed in the test, so a
    failure message shows what actually differed. A determinism test that reports only "hashes
    differ" costs an hour of bisection the first time it fails, and it will fail the first time

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a watched repository's own agent configuration → the agent's context | A repository ADL watches may carry settings, hooks, and instruction files authored by anyone who can write to it |
| the daemon's environment → a rendered prompt | The daemon holds forge tokens and model keys, and a prompt is persisted and later rendered into a pull request |
| declared context file contents → the prompt | Context files are repository content and are untrusted input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4-09 | Elevation of Privilege | a watched repository's hooks and settings executing in a headless session | high | mitigate | The auto-discovery-disabling flag is on every invocation with no configuration path that omits it, asserted by `test/argv.test.ts` across differing option sets. The vendor's own documentation records that without it a headless session runs a project's hooks in a folder nobody ever trusted, which is why this is a permanent requirement rather than a performance flag |

Persisted artifacts are therefore free of the daemon's environment by the same construction |
| T-4-35 | Tampering | an undeclared repository file joining the prompt because it is present | medium | mitigate | Context files are admitted only when declared in the effective configuration; a test places an undeclared instruction file on disk and asserts its content is absent from the render |
