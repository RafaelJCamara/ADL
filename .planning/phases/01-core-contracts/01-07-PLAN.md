<objective>
Give the target repository one validated, explicit contract for how ADL builds, starts, probes, tests, and tears down the app under test — with every command an argv array, every timeout a bounded duration, every path guarded, and every unknown key loud.

Purpose: SPEC-03 and SPEC-04 are the maintainer's side of the bargain. `.planning/REQUIREMENTS.md` § Out of Scope rules out auto-detecting build and run commands because it is non-deterministic where it matters most; `adl.yml` is explicit by design. D-22 records that this file is untrusted input under the stated trust boundary, so its schema is a security boundary as much as an ergonomics one. ROLE-07 promises ADL owns the app's lifecycle for *any* app, not only HTTP ones, which is why the readiness probe is a union of four kinds rather than a URL.

Output: `@adl/core/config`'s schema layer — commands, probes, durations, paths, and the pinned YAML entry point — with the parser's security posture proven by execution rather than asserted.
</objective>

Create `packages/core/src/config/yaml-parse.ts` exporting `parseYamlDocument(source)` as the *single* place in the repository where YAML is parsed. It uses the document-level API so that parse errors carry line and column (C-8) — config errors are shown to users, and "invalid YAML" without a position is a support ticket. Convert the document's collected errors into a `LoadError` carrying the first position. Pin the parse options explicitly in this one function with an adjacent comment naming, per option, the attack each default prevents: alias-count limiting stops resource-exhaustion via alias expansion; duplicate-key rejection stops last-wins ambiguity; single-document enforcement stops multi-document smuggling; unknown tags resolving inert stops deserialization-to-execution; merge keys being off stops merge-key abuse. 01-RESEARCH.md § Security Domain is explicit that these are defaults rather than guarantees, and that someone later adding merge support or a custom schema to "fix" a parse would silently re-open a hole — the comment block is what makes that a visible edit rather than an invisible one.

Create `packages/core/src/config/duration.ts` exporting `DurationSchema`, `parseDuration`, and `MAX_DURATION_MS`. Accept only strings matching a digits-plus-unit pattern over milliseconds, seconds, minutes, and hours — a bare integer invites exactly the ambiguity that has bitten every config format that allowed one, and a loose third-party duration parser accepts natural-language phrases and negative values. Keep the pattern linear, with no nested quantifiers. `parseDuration` returns milliseconds. Bound the result at `MAX_DURATION_MS` — pick a defensible ceiling of 24 hours and state it in the module header — because the YAML parser silently rounds oversized integers, so an absurd value must be rejected rather than accepted at a rounded magnitude. Reject zero: a zero timeout is always a mistake, and treating it as "no timeout" is the kind of implicit meaning this file format exists to avoid. Express the constraint with a structural pattern and a structural maximum, not a refinement, so it survives if any of these fields is ever published as JSON Schema.

Use a **strict** object at every level so an unrecognised key produces an issue naming the offending key rather than being silently dropped. A typo'd key that is quietly ignored is a setting the maintainer believes is in effect and is not — and a permissive object would also carry a prototype-polluting key through, which is the second reason 01-RESEARCH.md § Security Domain gives for this choice.

`version` is the literal 1 (`ADL_YML_VERSION`), so a future 2 fails loudly rather than being ignored. Document the promise narrowly in the module header, per 01-RESEARCH.md § Open Questions 2: within a major version ADL only adds optional keys, and a removed or renamed key requires a new version number.

`CommandSpecSchema` carries `argv` as a non-empty array of non-empty strings, an optional `cwd` validated through `RepoRelativePathSchema`, an optional `env` map, and an optional `timeout` validated through `DurationSchema`. Argv arrays rather than shell strings, always: no shell means no quoting bugs and no injection surface from repo config, and it keeps the shape compatible with the exec specification in ARCHITECTURE.md §5. `commands` carries `build`, `start`, `test`, and `teardown`, with `start` additionally carrying `ready` and `ready_timeout`.

`ReadyProbeSchema` is a discriminated union over four probe kinds (D-20): an HTTP probe carrying a URL and an optional expected status; a TCP probe carrying a port; a log probe carrying a pattern to match on the started process's output; and an exec probe carrying its own argv, which is the universal escape hatch for a database readiness binary or a probe script and which runs through the workspace exec path when Phase 2 lands it. New probe kinds are additive, so the union is the right shape rather than a string field with a lookup table.

Require `ready_timeout` whenever `ready` is present, and forbid it when `ready` is absent, using a cross-field refinement. A refinement is safe here and only here: `adl.yml` is not published as JSON Schema, so the emission hazard that bans refinements under the verdict layer does not apply. Add a comment stating exactly that, so the next reader does not "fix" a rule that is correct. SPEC-04 says an explicit readiness signal *and* timeout, which reads as both-or-neither (Assumption A7).

`context` carries `files` as an array validated through `RepoRelativePathSchema`, a bounded `max_bytes`, and an `on_overflow` enum over truncate and error defaulting to truncate. Phase 1 defines the field and its validation; Phase 4's prompt builder implements head-and-tail truncation. Making overflow an *error* an available option matters — silently truncating an oversized context file and proceeding is exactly the quiet degradation this project is designed against.

`pipeline` is an array whose entries are either a bare string naming a built-in stage or an object. Accept an object naming a harness with an optional `with` block and an optional `on_send_back` enum over continue and stop — Phase 1 only needs those fields to exist and validate; Phase 7 implements the policy. Accept the group syntax structurally and then reject it with a message naming it as a future capability, so the file format does not have to change when parallel stages land (D-23). Harness id *resolution* against the registry is plan 01-08's job; this schema validates shape only.

`limits` carries `max_rounds`, `budget_usd`, and `repeat_finding_threshold`, each bounded with a documented ceiling and a positive-integer or positive-number constraint — the YAML parser silently rounds oversized integers, so an unbounded numeric field accepts an absurd value at a rounded magnitude. `agents` carries per-role blocks with `backend`, `model`, and an optional `prompt_template`. Add a comment on `agents` recording that backend and credential selection is daemon-only and that plan 01-08 strips or rejects a repo-supplied value — the field exists in the schema so a daemon-level config can use the same shape, and D-22 makes the clamping explicit rather than implied.

`parseAdlYml(source)` composes `parseYamlDocument` with `AdlYmlSchema.safeParse` and returns either the validated config or a `LoadError` carrying the YAML position when the failure was syntactic and the Zod issue path when it was semantic. Take the file *contents* as a string — reading the file is the caller's job.
