Create `verdict.ts` exporting `OUTCOMES` (a frozen tuple of the six literals), `VerdictSchema` as `z.discriminatedUnion('outcome', …)` with one named member per outcome, and `consumesRound(verdict)` — a derived pure predicate returning true only for `send_back`, never a stored field. `pass` requires a non-empty `checked` array of `CriterionRef` (D-11). `send_back` requires a non-empty `findings` array. `warn` takes `findings` with no minimum. `skip` takes a `reason` and an optional `waiver`. `fail` and `inconclusive` each take a `summary` and a `reason`.

Two hard disciplines apply to everything under `verdict/`: (a) every constraint is expressed with a structural Zod combinator — `z.literal`, `z.enum`, `.min()`, `.max()`, `.length()`, `.regex()` — and NEVER with `.refine()` or `.superRefine()`, because `z.toJSONSchema()` drops refinements without a warning and would publish a contract weaker than the one enforced (Pattern 1, Pitfall 1); (b) every schema, including each member of every discriminated union, carries `.meta({ id: 'PascalName' })` so the emitted `$defs` are stable names rather than positional `__schemaN` (Pattern 2).

`fingerprintFinding` implements the discretion item from 01-RESEARCH.md § Open Questions 1: `sha256(stageId + NUL + normalise(title) + NUL + (location?.path ?? ''))`, where `normalise` applies NFKC, lowercases, collapses whitespace, and strips a trailing parenthesised line reference. NUL separators are included so a field-boundary collision is impossible. Line numbers are excluded because code moves (01-CONTEXT.md § Claude's Discretion). `sortFindings` sorts by severity in the order blocker, major, minor, nit, then by `fingerprint` ascending so equal-severity findings have a specified, stable order.

Create `hash.ts` exporting `sha256Hex(input)` over `node:crypto` — a builtin, not I/O, per the Architectural Responsibility Map. Create `errors.ts` exporting a `LoadError` class carrying a human-readable message and an optional source position, used by every loader in this phase.

Create `packages/core/src/verdict/aggregate.ts` exporting `RoundOutcomeSchema`/`RoundOutcome` and the total function `aggregate(verdicts)`. Implement D-09's discriminated union — `green`, `send_back` carrying a brief, `escalate` carrying a reason, `unverified` carrying the inconclusive verdicts — and D-10's precedence: `fail` short-circuits to escalate; otherwise any `send_back` produces send_back and carries every finding from every gate that raised one, because an inconclusive sitting alongside real findings usually resolves once the code changes; an `inconclusive` with no `send_back` anywhere produces unverified; only when every verdict is `pass`, `warn`, or `skip` is the result green. The empty verdict list is handled explicitly and never throws. Plan 01-04 proves this exhaustively; this task only needs it correct and total.

Create `packages/core/src/verdict/index.ts` re-exporting everything above.

Create `markdown.ts` exporting `loadAdlTemplateSpec(raw, featureId)`. It parses with `fromMarkdown`, requires a `# Title` heading and a `## Acceptance Criteria` heading (D-18), extracts criteria from TOP-LEVEL list items only so nested bullets remain inside their parent's byte range (D-19), and slices each criterion's `text` as the exact source substring between the list item's `position.start.offset` and `position.end.offset` — never a re-serialisation of the AST (Pattern 4). Assign `AC-1`, `AC-2`, … positionally in document order and store a `textHash` per criterion (D-01). A missing `## Acceptance Criteria` heading and a heading with no list items are two distinct `LoadError`s, so a spec can never enter the loop with zero criteria.
