<objective>
Build the two channels that sit beside the verdict union: the developer's own result — which structurally cannot say `pass` — and the infrastructure-failure channel that keeps "the gate broke" from ever being recorded as "the gate judged". Publish both, with the `Stage` interface, through `@adl/plugin-sdk`.

Purpose: CORE-03 gives a developer that believes a gate is wrong an honest alternative to subverting it — `.planning/research/PITFALLS.md` Pitfall 1 measures that mitigation at 92% down to 1%. CORE-06 says a malformed or unparseable verdict is an infrastructure failure, never a gate failure that costs a round. Both are cheap now and ruinous later: D-05 and D-12 are rated costly and one-way respectively, and D-12's return type is the interface third-party harness authors implement against, so it cannot be changed once published.

Output: `@adl/core/stage` and the `@adl/plugin-sdk` package, with the type boundary between `Verdict` and `StageError` asserted at compile time.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent output → `StageOutcome` | Model-produced text parsed into either a judgement or an infrastructure failure; misclassifying the second as the first costs the developer a round it did not earn |
| developer agent → its own result | The agent whose work is being judged reporting on that work |
| `@adl/plugin-sdk` → third-party harness authors | A published API surface that cannot be changed without breaking external gates |
