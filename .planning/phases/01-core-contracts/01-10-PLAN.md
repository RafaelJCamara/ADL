Create `packages/db/src/checksum.ts` exporting `CHECKSUM_TABLE`, `ensureChecksumTable(db)`, `recordMigrationChecksum(trx, name, digest)`, and `assertMigrationsUnmodified(db, migrationsDir)`. The table carries the migration name as its primary key, its digest, and the timestamp it was applied. This is **ADL's own table**, created by the runner the way the migration library creates its own: do not add a column to the library's bookkeeping table, because that table's shape belongs to the library and could change under a version bump. The library's table has exactly two columns and records no digest, so this guard is entirely ADL's to build — the precedent is the well-trodden schema-history checksum pattern that other migration tools ship and this one does not.

`assertMigrationsUnmodified` reads the applied migration names from the library's table, reads the recorded digests from ADL's table, recomputes each applied migration file's digest from its bytes, and raises on any mismatch or any applied migration with no recorded digest. The message names the migration, shows the recorded and found digests truncated, and states plainly that an applied migration must never be edited and that the correct move is to add a new one.

Wire it into `packages/db/src/migrator.ts`: ensure the checksum table exists, assert unmodified migrations **before** running anything, then record each migration's digest inside that migration's own transaction. Recording in the same transaction is what makes the two records consistent under a crash — a digest written afterwards can be lost while the migration stands, and one written beforehand can survive a rollback.

Add a comment in the runner recording the second half of the mitigation from 01-RESEARCH.md § Pitfall 5: take a file copy of the database before migrating. Phase 3 owns the daemon startup path that does the copying; the comment is the cross-reference so the two halves are not built independently.
