`mergeConfig` is a pure fold over three plain objects, in that order, with two rules that make it a security boundary rather than a convenience:

Implement this as an explicit clamp per field driven by a table rather than as a generic deep merge with a special case — a generic merge with an exception is where a newly added limit field silently arrives unclamped. A repo-supplied value for one of these is discarded and reported in the merge result so the daemon can log that the repository attempted it. A backend the watched repository can choose is a credential-selection primitive under a trust boundary that already grants code execution on the ADL host.

Freeze the result deeply before returning it. The effective configuration is snapshotted into the feature row at lease time, and changing `adl.yml` mid-flight must not change the pipeline of a running feature — a frozen object turns "we agreed not to mutate this" into a property.

Have `mergeConfig` return both the frozen config and a list of the repo-supplied fields that were clamped or discarded, so the daemon has something to log and the pull request has something to show. A clamp that happens invisibly teaches the maintainer nothing about why their configuration did not take effect.
