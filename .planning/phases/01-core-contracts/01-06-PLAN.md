<objective>
Complete the intake surface: both supported spec formats load into one normalized shape with one flat, individually addressable `AC-n` sequence and the author's original text retained verbatim beside it.

Purpose: SPEC-01 and SPEC-02 promise a maintainer can describe a feature either way and have it accepted. CORE-05 promises the criteria are enumerable and individually addressable with the original text kept verbatim. D-01 makes criterion numbering a one-way door — the id is embedded in every persisted finding, test result, send-back brief, and PR comment — so the extraction rule that decides *how many* criteria a document has is the highest-leverage detail in this phase. 01-RESEARCH.md verified by execution that the Gherkin parser accepts empty, scenario-less, step-less, and orphan-step files without throwing, so parser success is necessary and never sufficient.

Output: `detectFormat`, both loaders, and one shared id-assignment path, with the nine degenerate inputs proven to behave as specified.
</objective>

<assumption_delta_decision>
**Signal:** `assumption-delta scan 1` fired `kind: pluralization` on this phase. The genuine pluralization is the spec format: Phase 1 introduces a *second* way to describe a feature where a single-format design would have had one, and a second format is exactly the seam where an abstraction quietly keeps naming the first case.

**The noun that is now primary:** `NormalizedSpec` with a flat `AcceptanceCriterion[]`. The identity every downstream consumer joins on is `AC-n` on a `NormalizedSpec`, not "a markdown bullet" and not "a Gherkin scenario".

**Decision: `promote`.** The generalized representation is promoted to primary and both specific formats are demoted to details of one variant — `sourceFormat` on the spec and `kind` on the criterion. There is deliberately no parallel `SCN-n` namespace living alongside a still-primary `AC-n`, which is exactly the add-alongside shape this checkpoint exists to catch: a second namespace would let a Gherkin-sourced criterion be stored but never be addressed by the same coverage row as a template-sourced one. The behaviour tester branches on `kind` in its **prompt template**, never in the loader — one loader output shape, one addressing scheme, one coverage table. This carries D-02 forward; the human already chose it, and the rating there is one-way.

**Invariant test encoding the generalized intent** (accepted, implemented as Task 3): every acceptance criterion, for every supported source format, round-trips through the same `AC-n` addressing and carries a byte-exact verbatim `text` slice — `packages/core/test/spec/criterion-ids.test.ts`. It goes red the instant a future phase reintroduces a format-specific namespace or a format-specific addressing rule.
</assumption_delta_decision>
