<objective>
Build the pure lifecycle transition function — the one place a feature's state is allowed to change — with a state set that deliberately does not contain the gate pipeline.

This plan builds the function; plan 01-08 proves mechanically that resolving a longer pipeline leaves its bytes untouched.

Output: `@adl/core/state` — the state and event unions, the transition context and result, and a function exhaustively covered across the full state-by-event cross product.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker-reported events → the state engine | Events arrive from a separate process that may be stale, crashed and resumed, or replayed |
| state names → adopters' databases | Every state name shipped becomes a value in a database ADL does not own and cannot inspect |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-30 | Tampering | A stale worker writing over newer state | high | mitigate | Every transition result carries the state version the caller must guard the write on, so a write is structurally accompanied by its concurrency expectation. Phase 3 implements the conditional update and the fencing token; Phase 1 makes the guard impossible to forget by putting it in the return value. |
| T-1-31 | Repudiation | A state change with no audit record | medium | mitigate | Every applied transition returns exactly one feature-event effect to be written in the same transaction as the state change, carrying from-state, to-state, event payload, actor, and sequence |
| T-1-32 | Tampering | An invalid transition being silently absorbed | medium | mitigate | Undrawn pairs return an explicit invalid-transition value naming state and event rather than throwing or falling through to a default; the cross-product test proves no pair is unhandled |
| T-1-33 | Denial of Service | A state rename stranding in-flight features in adopters' installations | high | mitigate | State list is a frozen exported constant asserted by test, so a rename is a visible diff; the never-rename rule and the forward-mapping requirement are recorded in the module header |
</threat_model>
