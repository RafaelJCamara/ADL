features, one worker `SIGKILL`ed, the daemon restarted mid-flight — and prove the whole phase's
guarantees hold together, on both platforms.

phase.

  <action>
    Write one scenario test at `packages/manager/test/scenario/concurrency-crash-restart.test.ts`.

    **Setup.** A temp database on an ephemeral port with `concurrency.global` set to 3,
    `lease_ttl_ms` at about 200 and `heartbeat_interval_ms` at about 50 (real timers, small values,
    no fake clock). One repository, three queued features, each with a scripted worker that makes a
    real commit inside its worktree and records a `usage_events` row before completing.

    **The interaction.** Let all three features be leased. `SIGKILL` exactly one worker mid-run,
    after its commit and before its result. Then stop the daemon while the other two are still in
    flight, and restart it. That is three failures composed: a crash the fast path handles, a
    restarted manager with no child handle so only the reaper and the boot path can act, and enough
    concurrency that a bug in one feature's recovery is visible as damage to another's.

    **The five closing assertions, as D-32 enumerates them.**

    1. *All three features are accounted for.* Every feature is in a defined state and none is missing,
       stuck holding an expired lease, or duplicated.
    2. *Committed work is intact.* Each feature's commit is still reachable on its branch, including
       the crashed one — Phase 2's D-14 tears down worktrees only on terminal state, and D-12
       re-attaches rather than rebuilds, so nothing should have deleted it.
    3. *The spend ledger is unchanged by the crash.* `usage_events` rows written before the crash are
       present and identical; recovery writes none and deletes none.
    4. *No orphan worktrees remain.* After a GC pass, `listManagedWorktrees` reports nothing for a
       feature that no longer needs one.
    5. *No feature was ever double-leased.* See Task 1's audit helper below — this one cannot be
       asserted from a final snapshot.

    **`packages/manager/test/helpers/lease-audit.ts`.** Export `collectLeaseIntervals(events)` and
    `findOverlappingLeases(intervals)`. Reconstruct each feature's lease intervals from the
    append-only `feature_events` log — the `lease_acquired` and `lease_expired` rows, ordered by
    `seq` — and assert no feature has two intervals that overlap in time. A final-state snapshot
    cannot prove this: an overlap that opened and closed before the assertions ran leaves no trace in
    the current row, and the append-only log is the only place it is visible. Also assert each
    feature's `seq` sequence is contiguous with no duplicate, which the table's
    `unique (feature_id, seq)` constraint makes a real signal rather than a formality.

    **Keep it out of the fast loop.** `03-VALIDATION.md` deliberately excludes this scenario from the
    per-task quick run because of its runtime. Give it a name or tag that lets
    `pnpm --filter @adl/manager test` still include it in a full run while a developer can exclude it
    locally, and note the intent in a comment rather than wiring a second config.

    **No orphaned processes.** At teardown, assert `processIsAlive` is false for every pid the
    scenario recorded, including the one it killed and the two the restart orphaned. A scenario test
    that leaves processes behind poisons the rest of the CI run and is the most likely source of a
    confusing cross-file failure.
  </action>
