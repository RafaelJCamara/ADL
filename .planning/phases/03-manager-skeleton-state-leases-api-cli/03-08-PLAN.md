<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator terminal → control plane | A mistyped verb can stop every run on the host |
| GC sweep → the filesystem | The sweep deletes worktrees and scratch home directories |
| daemon config file → CLI process | The CLI reads the API token from the same file the daemon does |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-15 | Information Disclosure | CLI error output and process arguments | high | mitigate | The API token is read from the config file and passed in an `Authorization` header, never as a command-line argument (where it would be visible in the host process table) and never echoed in an error path; a test asserts the token string does not appear in any CLI stdout or stderr on the daemon-down and 401 paths |
| T-3-16 | Denial of Service | `sweepOrphans` reclaiming a live worktree | high | transfer | Owned by Phase 2, which built and tested the pass against the injected `FeatureStateLookup`; this plan binds the lookup to the real repository and adds no deletion logic of its own. The binding test asserts the lookup returns the persisted state, because a lookup that silently returned the absent value for every id would make every worktree look orphaned |
