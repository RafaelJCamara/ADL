## G-03-3 — the only gap this plan addresses

**Root cause, already diagnosed — no investigation needed.** `createControlState()` never touches the
database; the global pause flag lives in a JS closure and dies with the process. 03-07-PLAN.md's own
flagged assumption specified the fix direction ("a `meta` row and a boot-time read") and it was never

<design_decisions>
## The four decisions this plan makes, so the executor does not have to

**1. `absent` is not `paused`.** `getGlobalPause` returns a discriminated
`{kind:'absent'|'valid'|'invalid'}` result — the shape `getSchemaVersion` already established in this
same module, and for the same stated reason: a bare `boolean | undefined` collapses "never written"
into the same falsy signal as "written false", and a coerced garbage value compares as something. An
`absent` row means every database written before this change boots exactly as it does today.

**2. An unreadable value boots paused.** `invalid` resolves to *paused*, logged at `error` with the
raw value and the remedy. The two failure directions are not symmetric: wrongly resuming spends money
against an operator's explicit stop, while wrongly staying paused makes work wait until a human
looks. This is the same "check the limit before the spend, never after" reasoning 03-07 established
for the concurrency cap and Phase 6 inherits for the budget gate.

**3. Persist first, then flip memory.** If the write fails, nothing changed — dispatch keeps running
and the caller gets a named failure. The alternative (flip memory, then persist) recreates G-03-3
precisely: a brake that is engaged in this process and absent from the database. `adl kill` remains
the tool for "stop right now"; pause is a brake on new work, and one further dispatch tick during a
failed pause is bounded by the concurrency cap.

**4. The restore does not write back.** `restoreGlobalPause` reads and returns; it never re-writes the
row it just read. Writing back on every boot would reset `updated_at` and destroy the only evidence of
when the pause was actually set.
</design_decisions>
